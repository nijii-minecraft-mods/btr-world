# Подготовка BTR World к публикации

## Что уже подготовлено

- README с актуальной установкой, управлением, ограничениями и ссылками на полный справочник 113 крафтов.
- `description-en.md` и `description-ru.md`: тексты страницы.
- `project-fields.json`: заголовок, краткое описание, категории, лицензия, окружение и раскрытия.
- `CHANGELOG.md`: описание версии.
- GitHub workflow: проверки push/PR, сборка Java 21, GitHub Releases с постоянным именем JAR; готовый Action cloudnode-pro/modrinth-publish@v2.5.2.
- Offline-тесты readback и видимости проекта: сверка файлов/проекта, статусов версии, основного файла и исходников; обработка project `processing` с проверкой `requested_status`.
- `internal-previews`: существующие программные рендеры моделей для внутреннего планирования. Они не являются Minecraft-скриншотами и не предназначены для загрузки на Modrinth.
- `gallery/README.md`: кадры и подписи для настоящих скриншотов.

## Сначала учти текущие правила Modrinth

Проверено 4 октября 2026 года. Modrinth запрещает AI-изображения во всех частях страницы и публичную публикацию проектов, созданных преимущественно генеративным ИИ. Даже кодовые рендеры или SVG не следует выдавать за человеческие изображения для обхода правил.

У BTR World существенный AI-вклад в код, модели, текстуры, переводы и документацию. По доступной истории основная реализация создана ИИ по запросам и тестам Алиски. Поэтому текущий пакет ориентирован на **unlisted**, без обещания одобрения. Это не скрывает происхождение: включи раскрытия AI code/assets/text. Runtime AI нет.

- Правила: https://modrinth.com/legal/rules
- Объяснение: https://support.modrinth.com/en/articles/16551575-disclosure-and-usage-of-ai
- Раскрытия: https://support.modrinth.com/en/articles/16567675-content-disclosures

Решение о допуске остаётся за модерацией. Публичный GitHub-релиз можно использовать независимо от наличия страницы Modrinth. Не отключай раскрытия и не маскируй происхождение проекта ради допуска.

## 1. Подготовь реальный репозиторий GitHub

Загрузи содержимое каталога `btr-world` в свой репозиторий, а не вложенный ZIP. Сохрани `.github`, wrapper Gradle, `src`, `scripts`, `tests`, `release`, `docs`, LICENSE и README. Рабочие кеши/папки `build`, `run`, `release-assets` не нужны в git.

Default branch может называться `main`, `master` или иначе: workflow определяет её из GitHub. Сборки веток и PR не публикуются; успешный актуальный коммит default branch публикуется в GitHub Releases.

После первой успешной публикации стабильный URL:

```text
https://github.com/<OWNER>/<REPOSITORY>/releases/latest/download/btr-world.jar
```

Это шаблон, не уже работающая ссылка. Имя файла не меняется между версиями. Рядом публикуются sources JAR и SHA256. В истории остаются отдельные релизы. Повтор старого коммита не должен перезаписывать latest.

## 2. Создай проект Modrinth

Создай проект типа **Mod**. Заполни поля по `project-fields.json`, вставь текст из `description-en.md` или `description-ru.md`, укажи реальную ссылку Source и Issues своего GitHub. Лицензия собственной реализации — MIT. Не используй чужие кадры/обложки/записи без разрешения.

Окружение: **Client and server / Optional on client** (`server_only_client_optional`). Игра на сервере возможна без клиентского BTR World, но требует серверного Polymer resource pack. Локальный BTR World нужен для optional JEI integration и одиночной игры вместе с зависимостями.

Обязательные зависимости версий: Fabric API и Polymer. JEI — optional. Minecraft: 1.21.1, loader: Fabric. Для первой версии используй **beta**.

Включи раскрытия **AI-generated code**, **AI-generated assets**, **AI-generated text**. Прочитай правила с учётом текущего содержания. Настрой unlisted-доступность, если она доступна/разрешена для проекта; при необходимости обратись к модерации. Проект в состоянии approved/public не будет автоматически получать файлы от текущего workflow. Modrinth может возвращать `status=processing` во время проверки; preflight продолжит работу только если API явно показывает `requested_status=draft` или `unlisted`. При отсутствующем или публичном целевом статусе загрузка останавливается без изменения проекта.

## 3. Настрой Actions

В GitHub: **Settings → Secrets and variables → Actions**.

| Тип | Имя | Значение |
|---|---|---|
| Repository variable | `MODRINTH_PROJECT_ID` | ID или slug твоего существующего проекта |
| Repository secret | `MODRINTH_TOKEN` | Personal Access Token Modrinth, с VERSION_CREATE и доступом читать свой draft/unlisted проект (PROJECT_READ при необходимости) |

Не вставляй токен в чат, git, README или аргументы команды. Без `MODRINTH_PROJECT_ID` Modrinth-job пропускается; GitHub Releases продолжает работать. Если ID задан, а секрет отсутствует, uploader завершится понятной ошибкой.

Готовый Action загружает production `btr-world.jar` как основной файл и sources JAR как дополнительный `sources-jar`. Зависимости разрешаются по реальным IDs Modrinth. Description, icon и gallery не перезаписываются на каждом релизе: они заполняются отдельно.

## 4. Выпуски

1. Измени `mod_version` в `gradle.properties` и `release/CHANGELOG.md`.
2. Выполни проверки и игровой smoke-test ниже.
3. Push в default branch.
4. Actions создаст уникальную версию вида `0.4.0+build.<run_number>.<commit>`.
5. GitHub Releases получит новый latest со стабильными именами. Modrinth получит **listed beta внутри unlisted-проекта**, если настроены ID и token и проект разрешён.

Повтор запуска одного workflow не создаёт дубликат на Modrinth: сверяются version_number и SHA512 обоих файлов. Если version_number существует с другими файлами, загрузка останавливается. Если ответ Action потерян после загрузки, повторный запуск сверит уже созданную версию перед новой попыткой. Workflow старого коммита проверяет актуальный HEAD перед публикацией.

Локальная подготовка без публикации:

```bash
bash ./gradlew build
python3 scripts/validate_assets.py
python3 -m unittest discover -s tests -v
python3 scripts/prepare_release.py
python3 -m py_compile scripts/modrinth_release.py
```

Проверка синтаксиса ничего не отправляет и не требует token. Без настроенного реального проекта/репозитория внешняя публикация не выполнена.

## 5. Игровой smoke-test перед доступностью для других

Проверь в тестовом мире: принятие resource pack обычным Java-клиентом; все модели creative-вкладки; крафт предметов из каждой группы; приручение/ожидание/режимы движения/размножение; кормление малышей; репетицию каждого инструмента и её прерывание; коробку и выход Shift; отсутствие отталкивания игрока; четыре `/place template`; настенный и потолочный декор; сохранение после перезапуска.

CI проверяет компиляцию, генетику и ресурсы, но эти действия в игровом мире не выполняет.

## Музыка и права

В дистрибутиве только оригинальные нотные фразы и ванильные Minecraft-звуки. Записи аниме-саундтреков и узнаваемые транскрипции не включены. MIDI/нотная версия известной композиции не становится автоматически свободной от прав из-за другого тембра. Для публикации таких песен сначала нужен подходящий объём разрешений от правообладателей.

Собственная MIT-лицензия не передаёт права на франшизу. Не заявляй официальный статус.

Источник о различии композиции и звукозаписи: https://www.copyright.gov/register/pa-sr.html . Для конкретного использования музыки требуется проверка применимых прав и разрешений; здесь не заявляется универсальная лицензия на песни.

## Исправление загрузчика от 4 октября 2026

Самописный multipart uploader удалён. Загрузку выполняет готовый `cloudnode-pro/modrinth-publish@v2.5.2`.

Статус **проекта** остаётся draft/unlisted. Статус **версии** — listed, чтобы версия была в списке проекта. Это не переводит draft-проект в публичный и не отправляет его на модерацию.

`scripts/modrinth_release.py` выполняет только GET-запросы: разрешает ID проекта и зависимостей, проверяет совпадающие версии перед повторной загрузкой и подтверждает результат после Action. Проверка сверяет project_id, version_number, статус, SHA512 и имена двух JAR, primary file, sources-jar, Minecraft и Fabric. Несовпадение делает job красным. В Summary печатаются реальные ID и ссылка.

Для чтения ранее загруженной записи в окружении с секретом Actions:

```bash
python3 scripts/modrinth_release.py inspect --version-id C1jS82bQ
```

Это не меняет существующую версию. Старый unlisted-релиз не исправляется автоматически: следующий push создаст новую listed-версию. Секрет MODRINTH_TOKEN и переменная MODRINTH_PROJECT_ID используются прежние; нужны VERSION_CREATE, VERSION_READ и PROJECT_READ для закрытых записей.
